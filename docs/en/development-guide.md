- Node.js

If the Rust target is not installed, add it with:

```powershell
rustup target add wasm32-unknown-unknown
```

## Git Hooks

The first line of a commit message must use the following format:

```text
[type]: summary
```

Allowed types are `feature`, `fix`, `documentation`, `test`, `refactor`, `optimize`, `change`, `maintenance`, and `release`.

The commit message template is located at `.github/COMMIT_TEMPLATE.md`. The commit message validation hook is located at `.githooks/commit-msg`, and validation is performed by `scripts/check-commit-message.mjs`.

To enable the Git hook and commit template, review the contents and run the following commands manually:

```powershell
git config core.hooksPath .githooks
git config commit.template .github/COMMIT_TEMPLATE.md
```

## VSCode Extension Debugging

Open this workspace in VSCode and press `F5` to start the extension development host.

In the extension development host, run the following command from the command palette:

```text
CERT-C: ワークスペースをチェック
```

When `certC.analyzeOnChange` is enabled, only the changed C file is automatically reanalyzed during editing.

When `certC.analyzeOnSave` is enabled, only the saved C file is automatically reanalyzed on save.

Diagnostic messages and extension runtime messages are switched by `certC.messageLanguage`. Supported languages are `en` and `ja`, and the default for release artifacts is `en`.

When analyzing this repository itself, override `certC.excludeGlobs` in the workspace settings as needed to exclude extension-development generated files.

```json
{
  "certC.messageLanguage": "en",
  "certC.excludeGlobs": [
    "**/.git/**",
    "**/.svn/**",
    "**/.hg/**",
    "**/build/**",
    "**/cmake-build-*/**",
    "**/Debug/**",
    "**/Release/**",
    "**/dist/**",
    "**/vendor/**",
    "**/third_party/**",
    "**/analyzer-wasm/target/**",
    "**/node_modules/**",
    "**/out/**"
  ]
}
```
