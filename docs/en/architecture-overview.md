# Architecture Overview

> This English document is an automatic translation generated by Codex.
> The official source of truth is the Japanese version.

This project is implemented as a VSCode extension with a CERT-C rule engine.

## Principles

- The initial target C standard is C99.
- The analyzer core is implemented in Rust and called from TypeScript as WASM.
- External analysis tools are not part of the initial design.
- Embedded-environment differences and compiler extensions are represented by environment model files.
- The VSCode extension handles UI, settings, commands, and Problems integration.

## Structure

```text
VSCode Extension
  ├─ Commands
  ├─ Settings
  ├─ File discovery
  ├─ Automatic reanalysis control
  └─ Problems integration

Rust/WASM Analyzer
  ├─ Lexical analysis
  ├─ Preprocessor model
  ├─ Parser/AST
  ├─ Rule engine
  └─ Diagnostic output
```

The Rust/WASM side is split into modules for the WASM boundary API, analysis flow, lexical analysis, diagnostic model, and rule implementations.
Each CERT-C rule implementation is placed under `analyzer-wasm/src/rules/`.

## Current Scope

The current implementation is a minimal end-to-end implementation for detection test C code.

- `DCL37-C`
- `EXP31-C`
- `EXP45-C`
- `INT33-C`
- `PRE31-C`
